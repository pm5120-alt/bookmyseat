# BookMySeat acceptance traceability

## Current candidate addendum (2026-10-24, project evidence summary)

Final source test results recorded on 2026-10-24: SQLite 107 passed/0 failed/0 skipped; PostgreSQL 16.15 full suite 107 run/0 failed/1 skipped (SQLite-only refusal test); PostgreSQL concurrency module 8/8 passed; see `TEST_REPORT.md`. These results are historical evidence and were not all rerun in this deployment-preparation pass. The original ElevanceSkills assignment brief is not present in this project folder; task titles below follow the project's own matrix and are not independently checked against the official rubric. Razorpay payment completion, real SMTP delivery, Docker launch and public deployment remain unverified.

Ticket delivery's database path passed SQLite coverage for both Show and legacy no-Show bookings. PostgreSQL-specific tests cover lock-query compilation and refund lock ordering and were executed against PostgreSQL 16.15 for this source (8/8). Refund processing locks Booking before Payment, calls the provider outside the transaction, and rechecks state under the same lock order before persisting its response. The independent-connection PostgreSQL races of payment confirmation with cancellation and with refund passed.

Task 3 live Razorpay/provider reconciliation and Task 6 real SMTP-provider delivery remain unverified (PostgreSQL ticket locking and local Redis/Celery/SMTP-sink execution passed). Local deterministic tests cover malformed/mismatched provider-order reconciliation responses and the demo administrator's permission boundary. Discovery implements multi-select genre/language (OR within a field, AND across fields), same-show city/theater/date/time constraints, price sorting in both directions, stable pagination, filter-preserving AJAX/server parity, and history navigation. Recommendations award 2 points per matching genre and 1 per matching language, exclude already-booked and non-upcoming/inactive-show movies, and use trending fallback; recent-view history is capped at 30. Booking history pages 20 records and remains user scoped. The historical user-supplied benchmark JSON was preserved and its populated database was not accessed; a fresh 100,000-booking PostgreSQL seed and before/after-index comparison were run separately (`PERFORMANCE.md`). Historical external claims in rows below remain identified as historical rather than current verification.

The six task numbers below follow the project's traceability matrix: **1** movie management, **2** seat reservation, **3** payments and booking management, **4** analytics, **5** discovery, **6** tickets and email. Status describes both implementation and evidence. `BLOCKED` means the required external environment was unavailable; it is not a pass.
